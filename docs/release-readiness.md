# Готовность к публикации — 6 ноября 2026, учебная миссия

**Вердикт предрелизной проверки: техническую alpha `0.1.0a1` можно публиковать с перечисленными ограничениями; Git-тег — `v0.1.0-alpha.1`. Полный стабильный v0.1 по исходному ТЗ пока не принят.**

Это датированный снимок проверки **до первой публикации**. На момент фиксации приведённых результатов commit, push, tag, публикация GitHub/PyPI и deploy ещё не выполнялись. Этот документ не является индикатором текущего статуса GitHub-релиза; [release notes](releases/v0.1.0-alpha.1.md) описывают его состав. Локальные тесты не выдаются за результат будущего GitHub Actions run.

Первый вход теперь — локальный браузерный урок: прогноз → запуск → доказательство → собственное правило доступа → четыре проверки → смена пользователя → объяснение и экспорт. Старый CLI, двенадцать core cases, два явных control cases, три стандартных варианта защиты и Promptfoo execution path сохранены. Новые L01–L05 — отдельный учебный набор, не замена core.

Веб-интерфейс этой alpha — только учебная миссия. Испытательные матрицы и подключение живой модели доступны через CLI; live-путь реализован, но остаётся experimental и не принят на реальной reference-модели. Подключаемая модель действует внутри нашего ticket-agent, а не произвольного внешнего AI-приложения. Полноценный веб-интерфейс испытаний — будущая работа, не заявленная возможность этого релиза.

## Браузерный путь — выполнен, не только проверен по DOM

Через настоящий HTTP-интерфейс пройдены:

- Неверный прогноз не блокирует обучение; выбор попытки tool call не принимается за доказательство выдачи данных.
- Запрет всего проваливает нормальную задачу. Запрет одного ID проходит четыре начальные проверки, но проваливает L04 со сменой пользователя.
- Правило владения проходит чтение, запись, обычную задачу, безвредную цитату и перенос на другого пользователя.
- Reload и перезапуск сервера сохраняют шаг без повторного запуска. Отмена оставляет неполный результат, явный повтор сохраняет первоначальный прогноз.
- Подтверждение/отказ от нового урока, в том числе клавиатурой; старые сессии остаются в SQLite.
- Сохранение объяснения и скачивание JSON. Содержимое JSON точно совпало с сохранённой сессией; локального ключа доступа в нём нет.
- Узкий viewport **390 px** без горизонтального переполнения страницы; это не тест на настоящем телефоне. В проверенном браузерном сеансе console errors/warnings не обнаружены.

## Что исправлено и чем подтверждено

| Риск | Исправление / проверка |
|---|---|
| Старый запрос после сброса действует на новую сессию | Revision монотонна между сессиями; stale запрос отклоняется, история сохраняется |
| Отказ запуска worker навсегда оставляет «выполняется» | Ошибка создания потока снимает занятость, оставляет прогноз и допускает повтор; shutdown безопасен |
| Ложный успешный экспорт после потери материалов | Finish и export заново проверяют требуемые bundles; удаление evidence в изолированном тесте блокирует экспорт |
| Внешняя страница управляет локальным уроком | Loopback bind, случайный capability, строгие Host/Origin, закрытый API и ограниченные тела; негативные HTTP contracts |
| Смерть HTTP-parent оставляет опыт в фоне | Реальные process tests проверяют отмену admission, завершение child и группы Promptfoo |
| В source distribution попадают вложенные шаблоны runtime-кэша | Реальный build выявил пере-включение `.env.example` через вложенный ignore; excluded directories теперь не обходятся. Sdist и wheel заново собраны и проверены, UI assets присутствуют |

Первый Linux-прогон выявил **ошибку тестовой обвязки**, не продуктовый PASS: readiness мог прочитать ещё пустую таблицу run, а cleanup требовал отсутствующий в slim образе `ps`. Тест теперь ждёт настоящий pgid и проверяет Linux identity через `/proc`, не ослабляя проверку смерти процессов. Добавлены регрессии; исходные FAIL-логи сохранены, финальный полный прогон — 357 PASS.

Ранее проверенные fresh setup, установка из bootstrap Python 3.10 и terminal onboarding остаются [отдельным историческим пакетом](../examples/verification/2026-11-06/manifest.json). Их результаты не выдаются за новые наблюдения браузерной миссии. Новые интеграционные тесты также используют отдельные source/venv в папке с пробелами. Модели, зависимости и контейнерные образы в этой доработке не скачивались: использованы установленные инструменты и кэши.

## Повторить самостоятельно

После установки — `./lab start`; на чистом checkout сначала `./lab setup`. Модели и ключи для первого урока не нужны. Пройди маршрут без подсказок автора, попробуй заведомо неудачное правило и объясни, какой факт его опроверг. Затем проверь смену пользователя, скачай эксперимент и обнови страницу. Полный первый маршрут описан [здесь](start-ru.md).

Для инженерной проверки: `.venv/bin/pytest`, затем `./lab smoke`. Старое меню — `./lab start --terminal`, подключение своей модели — [отдельный маршрут](live.md). Каждый пользователь использует свой ключ у себя; ключ владельца проекта никому не раздаётся.
