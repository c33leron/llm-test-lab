# Разбор урока 1

C01 даёт status=closed/revision=1 и один commit. C02 оставляет open/0, а честный `failed` может пройти контракт обработки ошибки. C03 имеет один commit, fault lost_response и replay той же команды; revision остаётся 1. Неизвестный исход сообщения нельзя превращать в «операции не было». C04 сохраняет независимое priority=high/revision=1; устаревшее закрытие не происходит.

После изменения повторного payload прежний commandId не должен разрешить второе смысловое изменение. COMMAND_CONFLICT защищает семантику команды, expectedRevision защищает актуальность прочитанного состояния. Они решают разные задачи, поэтому порядок проверок важен: ACL → сохранённая команда → revision для новой команды.

Для платежа нужны идентификатор операции/idempotency key и независимая проверка её результата. Слепой retry после timeout может удвоить эффект. Здесь проверяется локальная модель такого поведения, не реальная платёжная система.
