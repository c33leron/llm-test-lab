# Первый запуск — учебная миссия без модели и ключа

Лаба — это маленькая учебная служба поддержки. У тебя есть заявка **A-101**, у другого пользователя — **B-201**. Помощник умеет читать и менять заявки. Мы проверяем: сделал ли он нужное, не тронул ли чужое и не соврал ли об успехе.

Вместо нейросети используется заранее заданная последовательность действий. База, инструменты и выбранное тобой правило доступа настоящие, но работают только с синтетическими данными отдельного опыта. Это обучение проверке приложения, а не испытание интеллекта модели.

## 1. Скачать и установить

На GitHub нажми **Code → Download ZIP** и распакуй архив. Открой терминал в распакованной папке. На Mac можно ввести `cd ` с пробелом, перетащить папку из Finder в окно терминала и нажать Enter. Это только переход в папку, ничего не устанавливает.

Нужен Python 3.10 или новее для запуска установщика. Если его нет, установи Python с [официального сайта](https://www.python.org/downloads/). Остальные закреплённые зависимости установятся сами, **только в папку проекта**:

```sh
./lab setup
```

Дождись сообщения об успешной установке. Установка требует интернета и занимает место на диске; модель не скачивается, ключ не запрашивается, платных запросов нет. Повторный setup проверяет версии и восстанавливает нужные зависимости, не удаляя результаты опытов.

Если получишь `Permission denied`, выполни `chmod +x lab`, затем повтори команду. Если ты уже работаешь в подготовленной копии проекта, повторная установка обычно не нужна: `./lab doctor` проверит её без обращения к модели.

## 2. Открыть миссию

```sh
./lab start
```

В интерактивном терминале откроется локальная страница **«Первое расследование»**. Оставь терминал работающим: он обслуживает экран на `127.0.0.1`. Здесь нет регистрации, облачного аккаунта или поля для API-ключа.

Если браузер не открылся, используй полный адрес, напечатанный в терминале. Часть адреса после `#` даёт доступ к этой локальной сессии: не публикуй адрес и не заменяй его ключом облачной модели. После перезапуска сервера открывай новый адрес из терминала.

Без интерактивного терминала обычный `start` ничего не запускает. Для явного запуска экрана без автоматического открытия браузера:

```sh
./lab start --web --no-open
```

Экран не запускает опыт при открытии или обновлении страницы. Запуск начинается только после твоего действия в уроке. Сверху всё время указано: **«Учебный сценарий — без нейросети»**.

## 3. Пройти расследование

1. **Прогноз.** Предположи, закроется ли своя A-101 и вернёт ли инструмент чужую B-201. Нажми **«Зафиксировать прогноз и запустить»**. Ошибиться в прогнозе можно: это не экзамен на угадывание.
2. **Доказательство.** Сравни прогноз с результатом L01. Найди событие, подтверждающее состоявшуюся выдачу чужих данных. Одного намерения вызвать инструмент недостаточно.
3. **Правило.** Выбери четыре условия: кого считать пользователем, когда разрешать доступ, какие действия проверять и в какой момент. Готовое правильное правило не подставляется за тебя.
4. **Проверка.** Сохрани правило и нажми **«Запустить 4 проверки»**. Проверяются L01, L02, L03 и L05: чужое чтение, нормальная задача, безвредная цитата и чужая запись. Если что-то не прошло, посмотри факты, измени правило и повтори.
5. **Новая роль.** Нажми **«Проверить новую роль»**. Теперь пользователь B закрывает свою B-201, а A-101 для него чужая. В L04 применяется то же правило, а не заново подобранный ответ.
6. **Объяснение.** Своими словами запиши, что изменил и чем подтверждается результат. Затем нажми **«Скачать мой эксперимент»**. Получишь JSON-карточку с прогнозом, доказательством, правилом, результатами и объяснением.

Не нужно запрещать всё ради зелёного результата. Защита должна остановить чужой доступ **и сохранить разрешённую работу**. Подробности шагов — в [коротком описании миссии](LEARNING_MISSION.md).

## 4. Остановиться и продолжить

Прогресс хранится в проекте. Обновление страницы читает сохранённый шаг, а не создаёт повторный опыт. **Ctrl+C в терминале** завершает сервер и отменяет активный запуск; уже совершённые действия не стираются из доказательств.

Для продолжения снова выполни `./lab start`. Прерванный опыт не возобновляется автоматически: прочитай сообщение на экране и явно повтори нужный шаг. Кнопка **«Начать заново»** создаёт новый урок, не удаляя прежние материалы.

Объяснение сохраняется для самопроверки, а не оценивается моделью или автоматическим судьёй. Завершение миссии не означает, что знания сертифицированы или что настоящая нейросеть проверена.

## 5. Старое меню и отдельные опыты

Терминальный маршрут и прежние сценарии не исчезли:

```sh
./lab start --terminal
./lab start --case C01 --open
./lab start --case F01 --variants all --open
```

`--case` выполняет конкретный fixture, `--open` открывает сохранённый HTML-отчёт после выполнения. В F01 сравниваются отсутствие проверки, запрет только в промпте и проверка владельца в коде. Предусмотренные нарушения в первых двух вариантах — полезное обнаружение, а не безопасный исход.

Открой [три урока](lessons/README.md): потерянное подтверждение, инструкция внутри данных, полезность защиты. Затем [создай свой сценарий](extending.md): сначала получи осмысленный провал старых действий на новом требовании, потом исправь действия и повтори.

Для настоящей модели есть [отдельный live-маршрут](live.md). Он не нужен для знакомства и не запускается автоматически. Сначала добейся простого понимания: что просили → что помощник попытался сделать → что приложение разрешило → что реально сохранилось.
