# LLM Test Lab v0.1.0-alpha.1

**The first technical alpha: a browser learning mission and a CLI experimentation lab for AI-agent security, quality and reliability.** Python package version: `0.1.0a1`. License: MIT.

This is **not a stable release, a production security certification, or a validated benchmark of live models**. The browser teaches and exercises a controlled scenario without a model. Live-model experiment support exists in the CLI, but remains experimental and unverified with a supported real reference model.

## Start without a model or API key

Download the repository/source ZIP and open a terminal in the extracted folder, or clone it:

```sh
git clone https://github.com/c33leron/llm-test-lab.git
cd llm-test-lab
```

Then install the project tools and start the lesson:

```sh
./lab setup
./lab start
```

Bootstrap requires Python 3.10+ and internet access to install pinned project-local tools. Setup does not download AI models or make paid model requests. If your ZIP extractor removed the launcher's executable bit, run `chmod +x lab` once.

When run from an interactive terminal, `./lab start` opens the Russian-language lesson in your browser. Keep that terminal running; `Ctrl+C` stops the local server. The UI binds only to `127.0.0.1`. For an explicit launch without opening a browser, use `./lab start --web --no-open` and open the full local address it prints. Do not publish that access link or expose the server through a tunnel.

## What is included

- **A guided browser investigation:** prediction → execution → evidence selection → a four-part access rule → four checks → changed-user transfer → reflection and JSON export.
- **Five learning cases, L01–L05.** A rule must stop forbidden access without breaking normal work. Denying everything or blocking one remembered ticket ID is not enough.
- **Twelve core cases and two explicit controls**, with vulnerable, prompt-only and server-enforced protection variants available through the CLI.
- **Actual synthetic tool effects and independent checks:** isolated SQLite state, durable events, task and security outcomes, and verifiable evidence bundles. Scripted actions are clearly distinguished from model-generated actions.
- **Saved progress and bounded execution:** refresh does not rerun an experiment; cancellation and restart do not silently promote partial results to success.
- **Preserved CLI workflows:** the earlier menu is available with `./lab start --terminal`; scenario runs, plans, comparisons, custom cases and machine-readable output remain available.
- **Experimental live-model transports:** Ollama and a Chat Completions-compatible protocol, with explicit profiles and live-run confirmation. Each user supplies their own local credentials; no project-owner key is distributed.

Live experiments use this lab's **ticket agent, tools, synthetic data and scenarios**. This alpha does not scan arbitrary external AI applications, and the browser does not yet provide the full experiment configuration/results workspace. You do not need to complete the lesson before using the CLI.

## Recorded validation

The 6 November 2026 pre-publication evidence records:

- **357 passing pytest tests on macOS arm64 and 357 on Linux/amd64 in Docker on an ARM host.**
- Ruff checks/format, strict mypy, schema drift and local documentation checks passing.
- **9/9 smoke and 36/36 core fixture attempts on each platform**, with no model calls. Expected vulnerable outcomes are not mislabeled as safe behavior.
- **108 verified attempt bundles:** 48 macOS release-control attempts, 45 Linux release-control attempts, and 15 attempts from the completed browser mission.
- A real browser journey covering wrong predictions/evidence, failed and corrected policies, transfer, refresh, server restart, cancellation/retry and downloaded JSON; a 390 px viewport check, not a physical-phone test.
- An expected F02 timeout control that preserves observed violations and leaves insufficient evidence inconclusive rather than reporting a false pass.

These are checks of the lab and its controlled scenarios. They are **not** live-model safety scores or independent novice-usability acceptance. The recorded local checks are separate from GitHub Actions status. See the [dated evidence](https://github.com/c33leron/llm-test-lab/tree/v0.1.0-alpha.1/examples/verification/2026-11-06-learning) and [detailed readiness boundaries](https://github.com/c33leron/llm-test-lab/blob/v0.1.0-alpha.1/docs/release-readiness.md).

## Known limits

- **No supported live local or cloud reference model has been accepted.** The intended two-model reference matrix is still **0/96 live attempts**.
- Independent first-use observation is still **0/2 novices**. Automated browser checks do not replace that acceptance step.
- The standalone Promptfoo viewer remains disabled because the pinned version cannot meet the required loopback-only binding. The lesson UI is a separate component.
- The current verified platforms are macOS arm64 and Linux/amd64 in Docker on an ARM host. Native Windows is not supported; macOS Intel and Linux arm64 are not verified here.
- The learner's explanation is saved for self-review; its meaning is not automatically graded.
- The browser is the teaching route in this release. Moving everyday experiment workflows into the web UI is future work, not a promised feature or delivery date for this alpha.

For a first run, read the [Russian getting-started guide](https://github.com/c33leron/llm-test-lab/blob/v0.1.0-alpha.1/docs/start-ru.md); for experimental model configuration, read the [live-run guide](https://github.com/c33leron/llm-test-lab/blob/v0.1.0-alpha.1/docs/live.md). Never commit API keys, `.env`, credentials or real personal data. Use only synthetic data in this lab.
