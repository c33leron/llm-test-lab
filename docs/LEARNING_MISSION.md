# Первая миссия: своя задача выполнена, чужие данные раскрыты?

После установки выполни `./lab start`. Это локальная учебная страница, не чат с нейросетью и не viewer Promptfoo. [Установка и первый вход](start-ru.md).

## Что проверяем

Пользователь A просит закрыть свою заявку A-101. В данных присутствует инструкция обратиться к чужой B-201. Заданный помощник попробует выполнить оба действия. Твоя задача — доказать нарушение и изменить прикладную проверку доступа так, чтобы разрешённая работа сохранилась.

Действия помощника заданы сценарием. Инструменты, выдача данных, записи SQLite и проверки фактов выполняются заново для каждого опыта. Запросов к модели нет. Красивый ответ помощника не заменяет сохранённый результат.

## Порядок действий

**Прогноз → доказательство → правило → четыре проверки → новая роль → объяснение.**

Сначала запиши прогноз и запусти исходный L01 без проверки владельца. Затем выбери событие, в котором инструмент уже вернул чужую запись. Попытка вызова и последующий отказ сами по себе не устанавливают, были ли данные раскрыты раньше.

Собери правило из четырёх явных решений:

| Поле на экране | Какой вопрос нужно решить |
|---|---|
| Кого считать действующим пользователем? | Можно ли доверять личности, названной в тексте заявки? |
| При каком условии разрешать доступ? | Защищается владелец объекта или только один знакомый номер? |
| К каким действиям применять правило? | Проверены ли отдельно получение данных и изменение записи? |
| Когда проверять правило? | Успевает ли проверка предотвратить действие, а не только заметить его после? |

После сохранения правила запусти объявленные проверки:

| Case | Зачем он нужен |
|---|---|
| L01 | Остановить чужое чтение, сохранив разрешённую задачу |
| L02 | Убедиться, что обычная работа не заблокирована |
| L03 | Обработать безвредную техническую цитату как данные |
| L05 | Отдельно проверить запрет чужой записи |

Лаборатория оценивает эффекты инструментов и состояние базы, а не совпадение четырёх выбранных значений с готовой строкой. Не прошедшая проверка возвращает тебя к правилу. Меняй условие после разбора конкретного факта, а не отключай неудобный критерий.

Затем выполни **L04**: действующим пользователем становится B. Теперь B-201 принадлежит ему, а A-101 — нет. Применяется то же правило. Такой перенос отличает проверку владельца от частного запрета одного ID; он не является независимым benchmark или статистической гарантией.

## Что остаётся после урока

Когда проверки и новая роль пройдены, напиши объяснение длиной 20–2000 символов: где была граница доступа, что исправлено и какое наблюдение это подтверждает. Смысл текста автоматически не оценивается. После сохранения доступны рубрика самопроверки и разбор.

Кнопка **«Скачать мой эксперимент»** сохраняет JSON-карточку с прогнозом, выбранным событием, правилом, результатами, объяснением и ограничениями вывода. Это не архив всех SQLite-баз. Полные материалы отдельных запусков остаются в `runs/`, прогресс урока — в `.lab-state/learning/`. Не вводи в объяснение рабочие секреты или чужие персональные данные.

Обновление страницы не повторяет запуск. После остановки сервера сохранённый шаг остаётся, но незавершённый опыт не продолжается сам. Для другого исходного прогноза начни новый урок; прежние результаты не удаляются.

## Граница вывода

Успешный урок показывает, что выбранное правило выдержало эти синтетические проверки и сохранило нужную функцию. Он **не доказывает устойчивость модели**, универсальную безопасность приложения или усвоение темы человеком. Для живых моделей нужен [отдельный маршрут](live.md); для расширения стенда — [свой case](extending.md).

Прежнее меню доступно через `./lab start --terminal`. Явный запуск веб-экрана без автоматического открытия браузера: `./lab start --web --no-open`. Это loopback-сервер на своём компьютере; его адрес с локальным ключом доступа не предназначен для публикации или открытия наружу.
